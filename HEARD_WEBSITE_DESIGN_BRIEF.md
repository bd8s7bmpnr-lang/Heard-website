# Heard Website Design Brief

This document is the product, brand, and design philosophy reference for the Heard website. Future website changes should preserve the intent captured here as Heard evolves.

## Product Overview

Heard is an iOS APRS exploration app by Ghost Wind Software.

Heard is not simply a packet viewer. The product goal is:

> Make APRS clear.

Heard helps users:

- Discover live APRS activity
- Understand stations
- Discover operator identity
- Follow moving stations
- Explore amateur radio activity in a modern Apple-quality experience

## Brand Identity

**Brand:** Heard

**Studio:** Ghost Wind Software

**Tone:**

- Thoughtful
- Calm
- Premium
- Technically capable
- Approachable
- Privacy-conscious

The product should feel like:

- An Apple utility app
- A carefully crafted independent software product

Avoid feeling like:

- An old amateur radio utility
- A cluttered technical dashboard
- A generic SaaS landing page
- A flashy startup marketing site

## Visual Language

Preserve:

- Dark navy and black backgrounds
- Subtle Earth horizon imagery
- Electric blue accents
- Clean typography
- Generous spacing
- Restrained animations
- Realistic iPhone presentations
- Premium but understated design

The design should communicate:

> Professional software made with care.

## Website Purpose

The website must serve four audiences:

1. Potential users who need to understand why Heard is valuable
2. App Store visitors who are deciding whether to download
3. Existing users who need support and privacy information
4. App reviewers who need a clear explanation of functionality and data usage

## Product Story Hierarchy

The website should tell this story in order:

1. **Explore**

   Users see live APRS activity.

2. **Understand**

   Users can identify stations and understand what they are.

3. **Discover**

   Users can see operator and callsign information through optional directories.

4. **Follow**

   Users can track moving stations with trails.

5. **Customize**

   Users control listening area, directories, and privacy choices.

## Key Differentiators

Highlight:

- Beautiful APRS map experience
- Station category visualization
- Callsign directory integration
- Offline local directory lookup
- Track Station with trails
- QRZ integration
- Receive-only APRS-IS experience
- Privacy-first design

Do not describe Heard as a surveillance tool.

Use language focused on:

- Stations
- Activity
- Signals
- Amateur radio exploration

## Screenshot Presentation

Real app screenshots are preferred.

Do not create fake app UI.

Screenshots should be presented as premium product experiences.

Preferred:

- Realistic iPhone device frames
- Clean spacing
- Apple-style presentation

Avoid:

- Floating raw screenshots
- Generic card grids
- Excessive decoration

## Copy Style

Writing style:

- Clear
- Concise
- Confident
- Human

Avoid:

- Excessive technical jargon
- Exaggerated claims
- Marketing hype

Preferred:

> Explore APRS activity around you.

Avoid:

> The revolutionary next-generation APRS ecosystem.

## Privacy Principles

Heard values:

- Local-first data handling
- User control
- Transparency

Important concepts:

- Location is optional
- Directories are optional
- Directory data is stored locally
- QRZ is external when requested
- No advertising or tracking claims unless true

Never invent privacy claims.

## Future Product Direction

Future enhancements may include:

- Richer Track Station insights
- Movement summaries
- Improved station relationships and context
- Deeper Ghost Wind product ecosystem

However, do not add future concepts to the launch site unless implemented.

## Website Design Rules

When making future changes, prioritize:

1. Clarity
2. Trust
3. Polish
4. Consistency

Before adding a design element, ask:

> Does this make Heard clearer?

If not, avoid it.
